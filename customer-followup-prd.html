验收场景

客户跟进认定与公海释放 PRD

V1.0需求评审稿更新时间：2026-10-26 10:28（北京时间）

业务背景：SCRM获取与客户相关的WhatsApp私聊或群聊后，会将聊天汇总到客户跟进记录。现有认定不限制实际沟通员工，可能出现客户负责人未参与跟进、其他员工的聊天持续延长该客户保护期的情况。

本期目标：将聊天归集与有效跟进认定分别处理。跟进记录展示实际沟通及AI总结；公海释放使用符合人员范围和客户关联条件的有效跟进时间。

适用范围：WhatsApp聊天自动跟进方式、相关客户与会话关联、跟进记录及公海计时联动。公海保护天数、既有领取/转交规则及其他跟进方式沿用现行配置。

已确认口径：有效跟进仅限客户负责人及对应运营；客户单方来信只提醒；已有有效跟进时间保留，新规则仅适用于生效后的消息。

修订说明

日期功能入口本次需求涉及角色
2026-10-26客户管理、SCRM、客户公海按实际沟通员工及客户关联认定WhatsApp有效跟进；跟进记录与公海计时分别留存结果。客户负责人、运营、SCRM使用人员

1. 客户管理：客户与人员关联

2 项需求

入口位置：客户管理 → 客户详情/编辑 → 联系人及人员信息；SCRM → 会话 → 客户/项目关联

1.1 客户联系人与内部人员识别CF01

入口：客户管理 → 客户详情/编辑 → 联系人及人员信息；SCRM → WhatsApp账号及会话
操作人：有客户资料维护权限的人员维护；系统读取关联并认定

  • 私聊对方依据客户已保存的主联系人及其他联系人关系识别，不限于创建客户当天的资料。内部员工依据实际发信账号/成员与现有组织人员的有效关联识别。
  • 有效跟进人员仅限该客户的客户负责人、对应运营。SM、设计师、交付人员或其他项目成员，不因项目关系、群成员身份而取得计入资格；同一员工同时承担该客户负责人或对应运营职责时，按其有效职责判断。
  • 客户联系人、聊天员工、客户负责人和对应运营分别保存标识。不得只按昵称、同名人员或账号登录者推定实际沟通员工；缺少可靠关联时按CF09处理。
字段/来源填写或读取要求校验与结果
客户及联系人读取客户唯一标识、主联系人、已关联其他联系人的WhatsApp身份；维护权限沿用客户资料权限。同一联系人存在多个客户归属且无法区分本次沟通时，不同时刷新多个客户。
客户负责人、对应运营读取该客户现有人员关系，使用员工标识及生效记录。按消息发生时的人员关系判断；当前人员调整不改写历史实际沟通人。
实际发信员工读取原始消息的发送成员及其已核实组织关联。群消息不能把拉取该消息的账号拥有者当成所有消息的发信人。共享账号无法区分时标为待核实。

1.2 客户群与客户归属CF02

入口：SCRM → 群会话 → 现有客户/项目关联区域
操作人：有该客户及会话关联维护权限的人员；系统读取已保存关联

  • 客户群与客户的业务关联需明确保存。关联项目时，校验项目所属客户一致；修改关联保留原关联、修改人及时间。
  • 单一客户专属群已确认关联后，客户加入助理、家属等外部联系人，不要求先将每位新成员登记为客户联系人。仍须满足指定内部人员实际参与及谈话归属明确的条件。
  • 客户拉人入群、群名称相似、员工仅加入群聊均不直接构成客户身份或有效跟进证明。多客户群按消息已明确关联的客户分别判断；无明确消息归属时为待核实，不对全部关联客户批量计入。
关联信息保存要求联动
群身份与关联客户使用SCRM已获取的稳定群标识及客户标识，名称仅作展示。识别单一客户群与多客户会话，不能仅凭群名称自动扩大客户范围。
关联项目有项目关联时，项目必须属于所选客户。项目关系帮助核对沟通范围，不自动扩大有效跟进人员资格。
关联维护结果保存成功后显示当前关联及维护时间；无权人员只读。重新认定仍使用原消息发生时间，并受CF08的规则生效范围约束；不按维护当天新增一次跟进。

2. SCRM：消息归集与有效跟进认定

3 项需求

入口位置：SCRM → 已登录WhatsApp账号 → 私聊/群聊会话 → CRM客户关联

2.1 消息归集、去重与时间依据CF03

入口：SCRM → WhatsApp消息同步 → 关联客户跟进记录
操作人：系统处理已获取且有权关联的原始消息

  • 保留消息来源账号、会话、消息唯一身份、实际发送人、发送时间及客户关联。文字、图片、语音、视频、文件等沿用SCRM现有可获取和展示的消息能力。
  • 同一原始消息因多个账号拉取、重复同步、重试或AI重新总结而再次到达时，不重复产生有效跟进结果；群聊尤其按实际原消息识别。
  • 消息发生时间用于有效跟进计时，同步时间及AI总结时间仅用于处理记录。历史消息晚到不得以当前时间延长保护期，具体生效范围见CF08。

2.2 私聊与群聊的计入条件CF04

入口：SCRM → 关联客户的原始聊天 → 自动认定
操作人：系统按客户身份、实际沟通员工及消息时间认定

  • 计入有效跟进须同时满足：消息可归属该客户；实际沟通员工身份可确认；员工符合CF01的人员范围；存在该员工实际发送的对客沟通消息。
  • 私聊按客户主联系人或其他联系人关联匹配；群聊按CF02确认的群/消息客户关系匹配。群成员身份、消息拉取账号与实际发信人分别识别。
  • 客户单方来信、负责人及对应运营尚未回应时，不计入有效跟进。在有权限的关联会话沿用未读/待回复提醒，跟进记录展示客户待回复提示，由当前负责人及对应运营处理；提醒本身不延长保护期。之后二者实际发送对客消息时，以该条发送消息的发生时间重新判断。
  • 账号登录、聊天同步、AI生成总结、群成员加入、阅读回执等系统或记录动作不作为员工实际跟进消息。

2.3 认定结果与重处理CF05

入口：消息自动认定结果；客户跟进记录 → 查看依据
操作人：系统生成；有权人员查阅或维护关联信息

  • 认定结果固定为计入、不计入、待核实。计入必须能追溯原始消息、客户、实际员工及当时适用的人员关系；不计入和待核实保存具体原因。
  • 人员、联系人或群关联修正后，重新核对对应消息，保留原结果、修正依据和规则版本；不把旧消息转换成当天新跟进。
  • AI汇总不替代规则认定。多人或多消息摘要须保留每条计入依据，不能将所有发言归为负责人跟进。
选项适用条件公海计时结果
计入客户、员工、人员资格及实际沟通条件均符合。按CF07更新，不重复、不倒退。
不计入关联清楚，但不符合人员资格或没有规定人员的实际跟进动作。保留沟通记录，不延长保护期。
待核实客户归属、实际发信员工或所需历史关系无法可靠确认。显示缺少的依据；核实前不作为有效跟进。

3. 客户管理：跟进记录与AI汇总

1 项需求

入口位置：客户管理 → 客户详情 → 跟进记录；SCRM → 已关联客户 → 跟进记录

3.1 记录展示与原始聊天追溯CF06

入口：客户详情 → 跟进记录 → WhatsApp来源记录/查看原始聊天
操作人：有该客户跟进记录及对应聊天查看权限的人员

  • 原有可获取、可关联的客户聊天继续按既有权限归集并提供AI总结，展示实际沟通员工及是否计入有效跟进。聊天可见与保护期计入分别处理，不把其他人的沟通显示为客户负责人完成跟进。
  • 同一汇总包含多位员工或不同认定结果时，分别列出实际参与者及计入依据。最新沟通时间与最近有效跟进时间分开展示；公海剩余时间使用后者。
  • AI总结保留原始消息关联。总结生成中、失败或重试不改写原消息及已完成的明确规则认定，不以总结生成时间新增有效跟进。点击原始聊天时重新校验会话权限。
展示字段/选项来源或组成校验与行为
来源及会话WhatsApp；私聊或群聊；可查看的会话名称/群名称。使用真实关联，群消息显示实际发信员工，不只显示拉取账号。
实际沟通人本段原始消息中的实际内部员工，可有多人。分别标明客户负责人、对应运营或其他实际角色；未知显示未识别。
沟通时间本次汇总覆盖的原消息时间范围。与同步时间、总结时间分开，使用统一展示时区。
计入结果与原因计入、不计入、待核实；对应原始依据及具体原因。混合结果不能把所有消息概括成全部有效；可查看实际计入的消息依据。
AI总结原有聊天汇总内容及其原始消息范围。显示生成中、已生成、生成失败；失败保留可查看的原消息并支持原流程重试。
客户待回复提示客户有新来信，但负责人及对应运营尚未实际回应时展示。沿用原会话未读/待回复处理结果；提示不能代替原消息查看权限，不产生新的有效跟进时间。
有效跟进时间本记录中符合条件消息的实际发生时间。没有符合条件消息时不填有效时间；不得用同步时间替代。
查看原始聊天打开本记录对应的原会话/消息范围。仅能读取原有权限范围；无权限说明原因，不扩展聊天可见范围。

4. 客户公海：计时与规则生效

2 项需求

入口位置：客户管理 → 客户详情 → 公海预警/归属记录；现有客户公海释放处理

4.1 有效跟进与保护期联动CF07

入口：有效跟进结果 → 客户最近有效跟进时间 → 现有公海释放判断
操作人：系统计时及释放；有权人员查看依据

  • 客户最近有效跟进时间取现有有效依据与本次符合条件消息发生时间的较晚值。旧消息晚到不使该时间倒退，也不按同步当天重新起算。
  • 不计入、待核实、重复同步或AI总结完成不延长客户保护期。现有保护天数及其他有效跟进方式继续按原规则参与计算，不因本次聊天认定调整而停用。
  • 释放前重新核对当前客户归属、有效跟进时间及既有释放条件。并发到达的有效跟进须纳入同一客户的最终判断，避免已跟进却仍按旧时间释放。
  • 聊天贡献与客户归属分别记录。其他员工沟通不会自动取得客户；领取、转交及客户归属变化仍走现有权限和业务操作。
信息计算/来源展示与追溯
最近沟通时间有权关联的原始聊天最新发生时间。用于了解客户沟通，不直接替代有效跟进时间。
最近有效跟进时间符合本规则的消息及其他既有有效跟进依据的最新时间。可追溯来源记录、实际沟通员工及认定结果。
保护到期/公海预警沿用现有保护天数、当前归属周期及释放条件。以有效跟进依据计算；具体天数读取现行配置，不在本需求中新增固定值。
释放结果现有公海规则执行结果。保留释放时间、所属周期及当时计时依据，不以事后摘要覆盖。

4.2 生效范围、历史记录与人员变动CF08

入口：新规则生效处理；既有客户人员交接/关联维护
操作人：规则启用按现有管理权限执行；系统留存生效与适用依据

  • 启用时保存已有最近有效跟进时间作为原计时依据，不追溯重算历史。系统留存实际生效时间T；仅消息发生时间达到T的消息按新规则认定。生效前的消息补拉、关联修正或重新总结，只补充沟通及依据，不按新规则重写启用时保留的有效跟进时间。
  • 规则生效时间和规则版本独立记录。消息时间与同步时间均保留；适用规则按实际消息发生时间及生效范围确定。
  • 员工交接后，新沟通按当时有效的客户人员关系判断。历史聊天及实际员工不改写；当前人员身份不能反推其过去一直具备资格。客户交接如何计算保护周期沿用原有交接规则。
  • 客户已进入公海或已由其他人员领取时，晚到历史消息不得静默改变客户归属或撤销已完成领取。保留证据及异常记录，归属调整仍按现有授权流程办理。

5. 权限、异常与处理事件

2 项需求

入口位置：客户资料维护、SCRM会话关联、跟进记录及现有公海处理

5.1 无法识别、同步失败及数据缺失CF09

入口：SCRM同步结果；消息认定结果；客户跟进记录
操作人：系统标记；有既有资料维护或同步处理权限的人员核实

  • 客户/群归属不明确、实际发送员工未识别、共享账号无法区分操作者或必要历史人员关系缺失时，显示待核实及具体缺项，不用当前负责人填补身份或编造计入结果。
  • 账号离线、消息同步失败及尚未拉取不是员工未跟进的证明。界面区分数据获取异常与已获取但不计入；保存原计时依据，公海异常处理沿用既有规则，不通过假造跟进时间掩盖同步问题。
  • 消息保存、判定保存及计时更新应保持一致；处理失败保留原记录和重试依据。重试不新增重复跟进，AI失败与明确规则认定分别处理。
异常记录与提示计时处理
客户或员工身份不明确待核实，列出缺少的客户/员工/群关联。核实前不计入，核实后仍使用原消息时间。
账号离线或消息同步失败显示账号/会话同步异常及最后成功同步时间（有记录时）。不产生虚构跟进，不把同步时间当客户沟通时间。
AI汇总失败显示失败，可按原流程重试，原消息仍可按权限查看。不撤销已成功的明确认定，不因重试新增续期。
历史人员关系缺失保留原消息及未知项，不能按现任人员回填历史。按CF08适用范围及现有历史依据处理，不编造资格。

5.2 权限与事件留痕CF10

入口：各业务入口保存/同步；跟进记录 → 查看依据；现有归属与公海记录
操作人：沿用客户、会话、人员维护和公海处理的现有授权范围

  • 客户可见不等于聊天可见，聊天可见不等于有权维护客户归属。读取原消息、维护关联、查看跟进及执行公海操作均校验对应权限。
  • 原始依据、实际员工、人员关系、认定结果/原因、消息/处理时间及规则版本可追溯。关联修正保存修改人和前后值，不覆盖原结果及历史人员。
  • 下列事件记录业务成功结果；失败和重试分别留痕，不能通过重复事件多次延长保护期。
动作事件记录内容对保护期的影响
消息首次入库原消息、会话、发送人、发生及同步时间。入库本身不直接延长，进入认定。
有效跟进认定成功客户、资格依据、结果、原因和规则版本。仅计入结果按原消息时间更新。
联系人/人员/群关联调整实际维护人、前后值和生效时间。调整本身不算新跟进，相关消息核对受生效范围约束。
AI总结生成/重试消息范围、生成状态、总结及处理时间。不新增或改变消息发生时间。
保护计时更新原依据、新依据及精确来源记录。使用较晚的有效时间，重复结果不重复更新。
客户释放公海释放时客户归属、规则及计时依据。按现有公海流程完成；不由聊天自动转交客户。

验收场景
