1.2.7 项目评分与等级

入口：项目详情 / 商机详情 / 关联待办 → 项目档案 → 项目评分及等级
操作人：系统计算；有查看权限人员查阅，有维护权限人员修改来源

  • 逐项展示取值、来源、得分 / 满分、总分、等级、计算时间和历史。产品品类按已承接商机去重；同品类加单不重复计类。设计需求取已承接设计商机及有效设计师，附件按项目实际保存的文件组计一次。
  • A：总分 ≥140，且类型和规模已填、已承接产品品类 ≥2、交期 ≤9 个月、存在参与计分的客户图纸附件或任一类设计图纸；全部条件须满足。B：100–139，或 ≥140 但 A 条件不足；C：60–99；D：<60。
  • 九个月内包括已封顶 / 前期规划、毛坯 / 即将装修、精装 / 装修中、旧改 / 翻新。达到 140 仍为 B 时，逐项列出未满足的 A 条件。
  • 首次项目保存、计分资料保存、商机承接或设计师关系、客户属性、邀约日期等有效更新后重算，保存依据及前后结果。未保存预览不作正式结果，失败保留原评分。
  • 例：客户属性5＋国家5＋别墅30＋1000–2000㎡20＋两个品类20＋6–9月20＋设计商机及设计师20＋两组图纸30＋到店0＋SCRM0＋DDP5＝155，A 条件齐全为 A；仅一个品类合计145，因品类不足为 B。
  • 各内部入口读取最新已保存等级，历史保留当时结果。评分不等同现实真实性、审批结论或成交，不创建 / 完成待办，也不改变报价和客户确认。
计分项 / 满分规则
客户属性 / 5已填写有效客户属性得 5 分；未填写得 0 分。各类客户属性采用相同分值。
项目所属国/地区 / 5已选择国家/地区得 5 分；未选择得 0 分。

  • 业务结果与事件在同次成功保存；权限、校验或保存失败不产生成功事件。重复操作及回执按事件标识去重，原记录持续追加。已保存事件通过服务端追加式审计存储保护，业务入口不提供修改或删除记录的能力。
  • 处理时间线在每次接手后的首个实际办理事件旁展示首次响应用时。首次响应用时从本次接手至该事件计算；更换负责人或同一人再次接回均重新计时。驳回后的等待补充时段，以发起人重新提交作为该时段的实际响应。转派本身、催办、查看和其他发起人的资料维护不计作当前负责人的首次办理；授权代办保留实际办理人。时间线保留交接事件和各次办理。

查看、取消、校验失败、保存失败及重复重试查看不作为实际响应；失败保留必要的接口 / 错误诊断，成功重试沿用原事件标识。不产生新的成功办理事件、不完成任务；外部发送失败不伪记业务失败或成功送达。

3.2.1 区域内分配

入口：分配商机任务 / 项目详情 → 分配商机 → 区域内分配
操作人：有项目维护及分配权限的 PM

  • 分配类型必选，默认区域内分配，另有跨区域申请、设计服务。同一项目可同时开展产品和设计业务。
  • 方案经理必选，显示负责项目区域且符合品类资格的 SM，支持姓名 / 品类搜索和多选，每个品类选一人；已选人员用可移除标签展示。
  • 转介绍人选填；填写后，转介绍原因、所选 SM 组长 / 主管同意截图必填。点击【提交转介绍申请】，为每位所选 SM 生成独立转介绍商机审批，待办由总经办办理。审批通过后直接生成该 SM 的产品商机及 PM 发起的报价任务，反馈 PM 并通知 SM；驳回须原因，发起人编辑原审批重提。
  • 产品分配使用已保存的完整项目空间，只读查看，不按本次商机选择范围。通过“补充项目空间”或“编辑项目信息”在同一抽屉维护当前项目，保存成功后自动返回原分配表单，保留填写内容。接单邀请或转介绍审批保存成功后完成源分配商机任务，办理后留在原页面。
字段 / 操作项选项 / 填写校验 / 联动
分配类型必选，默认区域内分配；另外两项为跨区域申请、设计服务单选类型后显示该类型字段，同一项目可分多次开展两类业务。

转介绍人选填，单选候选来自当前项目PM及现有PM / SM人员范围；选择后以下原因和截图转为必填。
转介绍原因 / 主管同意截图选择转介绍人后必填：原因文本、所选SM组长/主管的同意截图截图为图片附件；与当前分配申请一并保存，内部证据不对客发布。
提交无转介绍：发起采购商机接单；有转介绍：提交转介绍申请前者为每位SM生成接单任务；后者为每位SM生成总经办审批，审批通过才建立商机及报价任务。

3.2.2 跨区域申请

入口：分配商机任务 / 项目详情 → 分配商机 → 跨区域申请
操作人：PM 发起；当前总经办审批人员办理

  • 方案经理必选，可搜索多选，仅显示负责项目区域外且符合品类资格的人员；申请原因必填、附件选填。项目统一空间只读，通过按钮在同一抽屉维护当前项目后返回，保留人员、原因及附件。
  • 点击【提交跨区域申请】，为各申请生成独立总经办审批待办；下游任务保存成功后完成源分配商机任务。提交不修改项目空间。
  • 审批人查看项目、品类、接收 SM、原因及附件，点击通过直接生成正常商机和 PM 发起的报价任务，并反馈 PM、通知 SM，不再追加承接邀请。
  • 驳回须原因，PM 编辑原申请重提。提交和审批均校验人员资格、权限、当前项目空间及重复业务；失败保持原申请及状态。
字段 / 操作项选项 / 填写校验 / 联动
方案经理必选，可搜索多选，展示姓名 / 品类 / 负责区域仅项目区域外且具备品类资格的SM；同一品类最多选一人，重复校验与区域内共用。
项目统一空间只读数量与名称，提交时校验完整有效缺项点击“补充项目空间”，在当前抽屉切换项目编辑；保存并返回或放弃编辑后恢复分配，使用最新已保存空间。
申请原因必填，多行文本去首尾空格后非空，保留申请人和时间。
申请附件选填，多文件附件成功保存后随各独立申请关联。
审批动作通过、驳回；驳回原因必填审批人为总经办授权岗位；通过直接生成拟接收SM的商机与报价任务。

3.2.3 设计服务分配

入口：分配商机任务 / 项目详情 → 分配商机 → 设计服务
操作人：PM 发起；被选设计师主管承接

  • 必填设计师主管（可搜索多选）、设计期望完成时间、是否需要协调员。协调员选项为“是，由设计师安排”“是，我安排人员”“否，我自己确认”；选择由 PM 安排时，必须从有效人员中选择协调员。设计服务分配不校验或回写产品空间。
  • 界面备注：协调员将协助与客户确认设计图纸，完成设计定稿。每位主管的商机接单展示期望完成时间与协调方式；承接后保存到精确商机，设计单确认报价时写入设计中任务，并同步 GDS。
  • 每位主管收到独立商机接单，查看项目、附件、备注和发起 PM。提交成功完成精确源项目任务；后续仍可从项目详情分配其他业务。
  • 主管确认后生成设计商机及 PM 发起的报价任务。负责人填写设计费用、附件和备注，提交并确认设计单报价时，生成对应设计中任务并携带设计单信息同步 GDS。
  • 拒绝保留原因并通知 PM，由 PM 编辑原邀请重提；实际接受成功后才建立正常商机及关联报价任务。
字段 / 操作项选项 / 填写校验 / 联动
设计师主管必选，可搜索多选只列现有组织中设计师主管；不使用普通设计师或全员名单。同项目同主管已有商机或待接单邀请时禁止重复。

4. 商机管理

4 项需求

入口位置：商机管理 → 列表、商机详情；项目详情 → 商机列表

4.1 需求列表

需求项需求说明
列表、统计与详情按阶段和待办筛选商机，查阅对应报价和费用。
商机阶段与停留阶段按实际业务推进，记录每次进入时间并提示长停留。
方案经理交接同项目品类的原商机、加单及未完成任务统一移交。
商机输单有权限人员记录原因后终止该商机推进。

4.2 需求明细

4.2.1 列表、统计与详情

入口：商机管理 → 列表 / 详情；项目详情 → 商机列表
操作人：有商机查看权限人员；负责人按权限办理

  • 列表按创建时间倒序，支持商机号 / 项目号 / 订单号查询和列设置；展示阶段、停留、品类 / 设计服务、项目及客户、人员、金额和创建时间。
  • 过程卡片：待接收、洽谈中、报价中、待下定、待下单、交付中、已完成、待处理待办、停留超 10 天。金额区展示商机金额、成单金额及实收，按最终筛选商机汇总。
  • 阶段卡片筛选当前列表，再点取消；待处理卡片进入精确 BU 商机范围的待处理任务，前置邀请通过原任务及承接后关系追踪。行级查看待办保留历史查询能力。
  • 详情展示商机和项目资料、负责人、金额，以及唯一报价单 / 设计单和费用订单列表。每行显示单号、创建人、订单类型、费用类型、ERP 状态、部门、名称、覆盖率、贸易方式、金额、佣金、成单、实收、创建时间、报价状态及适用操作。
  • 报价历史仅查看该张报价单的成功提交版本。产品负责人创建 / 编辑报价，设计商机创建设计单；所有正常商机可创建费用订单或加单。
字段 / 操作项选项 / 填写校验 / 联动
商机状态筛选全部（默认）、待接受、已拒绝、洽谈中、报价中、待下定、待下单、交付中、已完成、已输单前置邀请与正常商机按各自权限提供操作，状态定义见「商机阶段与停留」。
快捷查询商机编号（BU）、项目编号、订单编号；查询 / Enter、重置新查询替换旧关键词，与阶段或卡片条件共同限定结果。
过程卡片待接收、洽谈中、报价中、待下定、待下单、交付中、已完成、待处理待办、停留超10天待接收统计待接受前置邀请；待处理待办进入当前BU范围待处理任务，其余筛选当前商机列表，再点取消。
金额卡片商机金额、成单金额；实收为补充金额按当前筛选商机及其关联费用汇总，项目直属费用不摊入商机。
订单列表类型报价单、设计单、费用订单费用订单另显示对应费用类型；每一报价行的历史仅限该单，设计单只属于设计商机。

4.2.2 商机阶段与停留

入口：商机管理 / 商机进度 → 当前阶段和停留
操作人：系统记录；有办理权限人员执行业务

  • 阶段及进入条件见下表；报价内容状态、客户确认、ERP 请求和业务阶段分别保存。费用订单不参与阶段判定。
  • 实际进入新阶段时记录进入时间，再次进入历史阶段按本次重计，并保留各次进入 / 离开记录。同阶段编辑、普通提交、交接及页面访问不重置计时。
  • 未结束且持续超过 10×24 小时时，用停留字段底色提示；恰好 10 天不标。已拒绝、已完成、已输单显示已结束，不继续积累；缺少可靠进入时间显示未记录。
  • 停留提示不自动输单、转交或催办。
  • 收款门槛按精确产品报价订单或设计单金额和该单实际累计 ERP 实收计算，含原单及各独立加单各自计算；不合并费用订单、其他商机或其他设计单的收款。缺失或无效的金额不作为达到门槛的证据。实际备货、交付完成和 GDS 完成的已保存事实优先，乱序回执不将已完成业务退回较早阶段。
商机状态进入与退出条件
待接受基于项目发出承接邀请，负责人尚未确认；确认后生成正常商机，转洽谈中。
已拒绝负责人拒绝本次承接。待接受和已拒绝均为前置记录，在商机管理及项目详情显示，只提供对应待办操作，不允许创建报价、加单或直接输单。
洽谈中负责人已接受商机；创建该商机唯一报价单后转报价中。
报价中已创建报价单，保存、提交及客户确认另用报价状态展示；负责人确认采购或设计报价后均转待下定。客户在线确认不代替负责人确认。
待下定采购与设计商机：负责人确认报价后，关联产品报价订单或设计单累计 ERP 实收尚未达到该单金额20%。实际收款达到或超过20%时转待下单；付款申请、费用款及其他订单收款不推进该商机。
待下单采购与设计商机：对应订单累计 ERP 实收达到或超过该单金额20%后进入。采购具备产品信息后由 PM / SM 在 ERP 点击备货，实际备货回执推进交付中；设计等待 GDS 确认收到该设计单款项的回执，再进入交付中。
交付中采购以 ERP 实际备货 / 生产结果进入；设计以 GDS 对精确设计单确认收到款的回执进入。ERP 实收金额本身、付款申请、图纸回传或设计定稿同步不能替代 GDS 收款确认。
已完成采购以关联产品订单正常交付结束的实际回执进入；设计以 GDS 完成该设计单对应“设计中”任务的回执进入。设计单收全款、图纸全确认或同步项目信息均不替代设计任务完成。
已输单有操作权限的负责人手动记录原因并输单，操作不可逆。已完成商机不允许输单；前置记录按原待办确认或拒绝处理。

4.2.3 方案经理交接

入口：项目详情 → 商机列表 → 修改方案经理
操作人：有项目维护及交接权限的人员

  • 选择符合该品类及适用区域资格的新 SM；同项目同品类始终一位当前 SM，原单和加单统一移交。
  • 保存后更新商机、报价编辑和未完成任务归属，以及两个报价总览显示；原编号、空间、状态、到达时间、已填内容、发布版本、客户确认和订单保留。
  • PM 交接同步对应项目任务及未完成职责，报价任务发起权归新 PM；客户、PM 和商机人员分别交接，不自动更换其他职责或设计师。
  • 历史发起人、处理人、提交人和通知人员保持当时记录。客户无需因交接重确认；保存失败维持原归属。
字段 / 操作项选项 / 填写校验 / 联动
新方案经理必选，单选；显示姓名、品类和负责区域候选须符合原品类及适用区域资格，不得选择不具备该品类职责的人员。
交接范围同项目同品类的原商机、加单、报价编辑职责、未完成任务一次保存同步当前职责；不修改已完成事件中的实际操作人。

4.2.4 商机输单

入口：商机管理 / 项目详情 / 商机详情 → 输单
操作人：有该商机输单权限的负责人

  • 仅正常且未完成的商机可输单，原因必填，保存后为已输单且不可逆；前置邀请通过原待办拒绝，已完成商机不可输单。
  • 商机和项目的输单分别处理。保留报价、订单、客户确认及办理历史，失败保持原状态。
字段 / 操作项选项 / 填写校验 / 联动
输单原因必填，多行文本去首尾空格后非空；仅有权限且尚未完成的正常商机可提交。
提交输单、取消成功进入已输单且不可逆，保留原报价 / 订单 / 历史；取消不改状态。

5. 商机报价与 ERP

6 项需求

入口位置：商机详情 / 产品报价或设计报价任务 → 对应单据；ERP → 收款与履行

5.1 需求列表

需求项需求说明
产品报价单每商机一张报价，使用现有线上报价模板填写产品。
设计单设计商机按服务费用报价，创建确认后发布两端总览。
保存、提交与客户确认区分内部工作稿、正式发布及客户确认。
负责人确认报价确认已提交的有效版本，完成原报价任务并提交 ERP。
ERP 收款与履行ERP 实际回执驱动交付，产品和设计使用各自条件。
商机加单已承接产品及设计商机可在各阶段追加独立需求。

5.2 需求明细

5.2.1 产品报价单

入口：产品商机详情 / 报价任务 → 创建 / 编辑报价单
操作人：当前商机 SM

  • 记录项目、商机、当前负责人、品类、原单 / 加单和精确报价任务关系；重复创建返回已有报价。
  • 带入项目当前全部空间，SM 在所需空间录入本次产品；其余空间保留空产品列表。报价内容只属于本商机品类；产品选择、模板字段及计算沿用现有报价能力。
  • 保存仅更新工作稿，两端继续使用最近有效提交。产品提交须匹配完整当前空间及名称，不校验顺序；空间版本变化提示按最新范围核对。

5.2.2 设计单

入口：设计商机详情 / 报价任务 → 创建 / 编辑设计单
操作人：当前设计商机负责人

  • 字段：设计费用必填，附件、备注选填；附件可上传相似作品供客户查看。只有设计商机具备该入口，设计单属于该商机唯一报价。
  • 确认创建校验有效费用、附件和商机关联，发布两个总览并保存成功提交历史；后续保存只更新工作稿，重新提交发布新版本。
  • 设计服务不校验产品空间；设计任务和 PM 审核完成与否不限制设计报价。仍由报价任务「确认报价」提交 ERP 并完成任务。
  • 设计单及费用订单沿用既有 XF 开头单号，系统生成并保持唯一；单号是任务、项目和 ERP 记录的关联依据。
字段 / 操作项选项 / 填写校验 / 联动
设计费用必填，大于0的有限数值保存为该设计商机的唯一设计报价金额，不与费用订单共用记录。
附件选填，可多文件可以包含供客户查看的参考作品；只发布明确允许对客的资料。
备注选填，多行文本随设计单保存，按提交版本进入总览及GDS关联资料。
设计单号只读，系统生成XF开头唯一编号与报价任务、设计中、设计定稿及ERP记录精确关联。

5.2.3 保存、提交与客户确认

入口：报价编辑 → 保存 / 提交；客户报价链接 → 确认报价
操作人：SM / 设计负责人；客户

  • 待报价：已创建尚未保存；已保存：工作稿已保存；已报价：本次提交成功；已确认：客户确认该发布版本。负责人确认报价和 ERP 执行另记结果。
  • 产品提交校验商机权限、唯一报价、品类、当前完整空间和模板适用规则；设计按服务费用及资料校验。保存不发布、提交失败不对客生效。
  • 提交成功原子更新项目及客户总览，保存不可覆盖的报价快照、提交人和时间。重新提交发布新版本，使该批次当前客户确认恢复未确认；历史继续可查。
  • 仅保存、提交或客户确认均不完成报价任务；从待办创建 / 编辑并提交后留在待办中心，供负责人继续确认。重复提交同一请求不新增历史或重复通知。

5.2.4 负责人确认报价

入口：报价任务 / 商机报价行 → 确认报价
操作人：当前商机 SM 或设计负责人

  • 允许已报价或客户已确认的当前有效版本；客户确认不是前置条件。已保存编辑稿、待更新或冻结后不允许的版本不能确认。
  • 成功保存实际确认人、时间、报价及价格版本和 ERP 请求，完成该商机及报价单的精确报价任务，并独立通知当前 PM；办理后刷新原页面，待办中心办理继续留在待办中心。
  • 报价任务由当前项目 PM 发起、商机负责人负责；客户确认只更新报价确认记录，不代替负责人操作。
  • 请求初始 ERP 执行状态为未执行；请求、接收、实收与执行分别记录。同版重复确认返回原结果，失败不完成任务、不发送成功通知。
  • 采购与设计商机确认报价后均进入待下定，对应产品报价订单或设计单累计 ERP 实收达到该单金额20%后进入待下单。设计单确认报价时即同步至 GDS 并生成设计中任务。确认报价不表示收到款或实际备货。

5.2.5 ERP 收款与履行

入口：ERP → 关联产品报价订单 / 设计单；CRM → 回执结果
操作人：财务在 ERP 收款；产品备货由 PM / SM 在 ERP 操作；GDS 回传设计收款确认和设计任务完成

  • CRM 发送精确项目、商机、报价 / 订单、版本和金额。ERP 接收、实收、备货 / 生产和完成回执分别留存，重复回执不重复计款，旧版本不能覆盖新业务结果。请求或付款申请不代表真实收款。
  • 产品先完成正式报价并由负责人确认，商机进入待下定。该产品报价订单累计实际收款达到或超过订单金额20%后进入待下单；具备产品信息后由 PM / SM 在 ERP 点击备货，实际备货回执推进交付中，正常交付结束推进已完成。
  • 设计单确认报价后进入待下定，同时同步 GDS 并生成设计中任务。财务仍在 ERP 收款；该设计单累计 ERP 实收达到或超过单金额20%后，商机进入待下单。GDS 确认收到该设计单款项并回传 CRM 后进入交付中；GDS 完成该单对应设计中任务后进入已完成，不按收全款直接完成。
  • 设计定稿逐图确认及同步与设计中任务独立完成。同步项目信息不结束设计中任务，也不据此完成设计商机；GDS 任务完成不替代未完成的图纸审核。费用只计金额，不参与上述状态判定。
  • 产品备货前重新提交更新同一关联订单的报价版本，保留单号、真实实收和执行记录；普通保存不更新已发布或 ERP 内容。已备货及后续原报价 / 订单冻结，新增需求通过独立加单。
  • 接收或发送失败保留原内容及可追溯重试；确认成功后的发送失败不伪造 ERP 成功或撤销已保存办理结果。
  • 校验示例：设计单金额1000元，累计 ERP 实收199.99元时仍为待下定，达到200元时进入待下单；仅实收增加不代表 GDS 已确认收款或完成设计。
业务事件精确关联与结果
采购订单 / 设计单实收回传按项目、BU 商机、精确产品报价订单或 XF 设计单及收款记录校验；该单累计 ERP 实收达到或超过单金额20%时，从待下定进入待下单，并重新计算项目成交状态。重复回执不重复计款，费用订单及其他订单收款不合并。
采购备货回传仅实际备货 / 生产结果推进交付中；创建 ERP 请求、达到收款门槛不代表已备货。
GDS 确认收到设计款校验来源、事件标识、项目、BU 商机、XF 设计单、对应设计中任务、处理人及当前任务版本；留存确认时间和原回执，进入交付中，不修改 ERP 实收。
GDS 完成设计中结束精确设计中任务并将该设计商机推进已完成；其他设计单、定稿任务及未确认图纸不随之完成。
失败、重复与乱序重复事件返回原结果；关联不符、越权、陈旧版本或保存失败不更新业务状态。已完成事实不因较晚到达的收款通知回退。

5.2.6 商机加单

入口：商机列表 / 详情 / 项目商机行 → 商机加单
操作人：有来源商机加单权限的人员

  • 不设备货或确认报价的开放门槛；校验来源、当前负责人及操作权限，自动记录承接完成并生成独立加单商机和 PM 发起的报价任务。
  • 沿用当前负责人并保存来源商机 / 原订单关系。设计加单生成独立设计商机和设计报价任务；该加单设计单确认报价后才生成对应设计中任务。
  • 产品加单使用项目完整当前空间，只录本次新增产品及数量，空空间允许无产品；设计加单按新增服务及费用报价。
  • 原单与每次加单分别发布、确认、计款和保留历史，本次客户确认不要求重确认原单或其他加单。

6. 费用订单

3 项需求

入口位置：项目 / 商机 → 费用订单；待办中心 → 费用订单

6.2.3 费用金额统计

入口：项目 / 商机列表、详情及商机进度 → 金额
操作人：系统按当前查询范围汇总

  • 创建成功的费用金额计入对应项目金额及成单金额；关联商机的费用还计入该商机金额及成单金额。项目直属费用只计项目，不分摊到其他商机。
  • 实收取该费用订单实际 ERP 收款，未有真实回款不增加实收。ERP 请求、失败或执行状态不代替收款金额。

  • 例：产品商机金额1000、成单600，新增关联费用300后，商机金额1300、成单900；项目另有直属费用200，则项目费用增量为500，商机仍只增加300。
  • 费用的创建、传输、收款、备货或完成均不推进项目 / 商机阶段，也不改变产品或设计报价状态、客户确认及报价任务。

  • 由设计师安排协调员时，GDS 回传协调员身份及逐图确认结果；CRM 展示这些结果，PM 核对后手动同步项目信息。由 PM 指定协调员时，该人员与 PM 均可在 CRM 确认、驳回和同步对应图纸，操作记录实际处理人。
  • CRM 与 GDS 请求及回执检查系统、任务、项目、商机、设计单、处理人、事件标识和版本；重复回执返回原结果，陈旧版本、关联不符或保存失败不得改动任务、图纸或附件。
  • GDS 确认该设计单收到款后向 CRM 回传，商机进入交付中；GDS 完成精确设计中任务时商机进入已完成。两种回执各自留存来源、事件、实际处理人及时间，与设计定稿任务独立。

9.2.2 逐张图纸确认与重提

入口：CRM 待办中心 → 设计定稿 → 查看并处理；GDS → 原设计任务 → 被驳回图纸修改与回传
操作人：项目 PM / PM 指定协调员；原设计师处理驳回；GDS 协调员在 GDS 确认

  • CRM 列表在副标题显示关联 XF 设计单号；设计中任务和设计定稿沿用同一设计单关联。审核主操作为查看并处理，催办为次操作。审核界面展示设计单信息、期望完成时间、协调方式、协调员及本批全部图纸。每张独立展示类型、文件、版本、说明、状态、实际审核人及历史。打开界面不改变任务状态。
  • PM 或 PM 指定协调员可逐张确认当前待确认版本，或填写原因驳回该图。仅退回有问题的图纸给原设计师，同批其他已确认图纸保留结果；父审核待办保持待处理。选择由设计师安排协调员时，CRM 展示 GDS 已确认结果，PM 负责同步。
  • 原设计师在 GDS 修改被驳回图纸并回传 CRM。沿用图纸标识和原审核任务，追加版本及提交历史，清除该图当前驳回标记并通知 PM 及其指定协调员；已确认图纸不能覆盖。
  • 仅当本批全部图纸已确认，才可点击“同步到项目信息”。有待确认或已驳回图纸时不可同步；同步成功按类型归档到项目的四类图纸附件组、重算资料评分并完成本批设计定稿。其他附件、历史审核及产品空间保持关联。
  • 同步不完成设计中任务，设计中任务由 GDS 决定完成。同步操作校验权限与当前图纸版本；重复同步不重复归档；保存失败保持图纸、项目及任务原状。

10.2.2 通知卡片与精确入口

入口：企业微信应用消息 → 查看待办 / 查看报价 / 查看结果
操作人：对应接收人员

  • 共用一个「敬城 CRM」自建应用，采用textcard。标题为业务事件；正文含时间、实际发起人、客户、项目、品类 / 设计服务、真实报价版本、批次、当次状态及原因摘要。
  • 发起人记录触发该事件的实际人员及当时姓名；客户未经身份认证时写“客户链接确认”，系统事件写“系统自动触发”，历史缺值写未记录。不展示私人手机号或待办内部修订次数。
  • 待办 / 审批通知进入待办中心精确搜索原待办，清理旧状态、人员和停留筛选，关系为全部；详情由用户主动打开。客户确认通知定位原报价任务。
  • 报价通知定位项目及品类，订单结果定位对应订单；登录后保留原目标，重新校验当前权限、归属和状态，已完成不重复办理。
  • 历史卡片保留发送时内容、发起人及原因，当前任务显示最新状态，旧驳回通知不恢复驳回。正文过长截为摘要，详情保留完整记录，动态内容转义并按接口长度校验。

10.2.3 去重、发送结果与催办

入口：服务端 → 企业微信发送记录；待办中心 → 催办记录
操作人：系统发送，有权限人员处理失败

  • 按业务事件、精确记录、报价 / 提交版本或状态变化及接收人去重。同次重试不新增通知；同一待办再次成功修改 / 重提必须生成新事件，不能只按待办号去重。
  • 状态为待发送、接口已接受、发送失败、结果未知。接口成功不等于已读 / 已办理；无效成员逐人记失败，超时先核对原请求。通知失败不撤销已成功业务。
  • 保存实际事件及版本、发起人和当时姓名、接收成员、应用、发送内容、触发时间、每次尝试、接口结果与重试次数；凭证仅服务端管理。历史已发内容不随交接或改名变化。
  • 重试沿用原事件；办理通知发送前核对最新归属，已发送历史接收人保留。防止重复建发送任务，但不承诺企微客户端绝对仅出现一次。
  • 催办按原待办滚动24小时限制，内容含实际催办人、项目、任务、期望日期和逾期情况；接口成功后计冷却，失败不占额度，结果未知先核对原记录。
  • 接入使用测试应用和成员验证手机 / PC、登录续跳、定向接收、完整原因及发送失败；实际业务完成仍取 CRM 成功保存结果。
