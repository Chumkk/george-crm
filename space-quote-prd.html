空间报价 PRD

V1.60更新时间：2026-10-19 15:21（北京时间）功能需求说明

本期围绕项目、商机及待办串联产品报价、设计协作、费用订单和客户确认。各模块先列需求项，再说明入口、操作人、字段校验及完成后的流转。

1. 项目管理

5 项需求

1.1 需求列表

需求项需求说明
创建与编辑项目保存客户关联、项目资料、空间与附件，创建成功生成 PM 分配商机任务。
项目空间项目内全部产品商机及加单共用完整空间范围。
项目列表与统计按设计业务、待办和推进情况筛选项目，金额随当前结果更新。

1.2 需求明细

1.2.1 创建与编辑项目

入口：项目管理 → 创建项目；项目详情 / 项目档案 / 分配商机任务 → 编辑项目
操作人：有创建或项目维护权限的 PM

  • 创建使用右侧抽屉，分为基础信息、项目信息、物流方式、其他补充信息。图纸和备注属于项目信息；各字段要求见下表。
  • 表单展示适用必填项的完成进度、分区导航和缺项定位。创建时以填写进度引导；保存后计算正式评分及等级。编辑已有项目可查看未保存的评分预览。
  • 创建成功保存唯一项目、客户关联及附件，生成一项由项目 PM 负责的分配商机任务。编辑保存更新同一项目并留存前后值、修改人、时间和来源，编辑本身不完成分配商机任务。
  • 客户可关联多个独立项目；各项目、商机、任务及报价分别关联。同次提交重试返回原项目和任务，失败保留输入并回滚本次业务。
  • 平面设计图、3D意向图、全屋3D图、其他图分别提供上传、预览及附件维护，项目档案按同样分类展示。各组保留附件的来源设计单、审核批次、图纸标识与版本，项目维护与审核归档共用同一分类。
字段填写要求校验 / 来源
客户必填，编辑时只读创建项目时保存唯一客户关联；客户自身字段在客户入口维护。
项目名称必填去除首尾空格后非空。
项目所属国/地区必填选择有效国家/地区。
项目经理 PM、交付经理分别必填人员有效；分配商机任务归当前 PM。
项目商务经理、PM 助理选填填写时人员有效。
项目类型必填完成对应具体类型选择。
项目类型说明条件必填项目类型为其他时非空。
项目规模选填选择有效规模档位，保存后参与评分。
项目进展/交货周期必填选择有效档位，物理建设进度与商机成交阶段分别展示。
项目空间选填，产品分配时必填每个填写名称非空且唯一；稳定标识由系统保存，变更按 项目空间 核对影响。
现场照片/视频、客户图纸/附件选填，支持多文件文件上传成功且类型/大小等通过 附件 校验；保留文件标识、来源及上传记录。
平面设计图选填，分别支持多文件项目维护人上传或由已完成的设计定稿按对应类型归档；有效保存图纸按 项目评分与等级 计分。
3D意向图选填，分别支持多文件项目维护人上传或由已完成的设计定稿按对应类型归档；有效保存图纸按 项目评分与等级 计分。
全屋3D图选填，分别支持多文件项目维护人上传或由已完成的设计定稿按对应类型归档；有效保存图纸按 项目评分与等级 计分。
其他图选填，分别支持多文件项目维护人上传或由已完成的设计定稿按对应类型归档；有效保存图纸按 项目评分与等级 计分。
项目描述与客户关注点、备注选填保存项目需求说明和设计业务带入内容。
物流方式必填选择有效物流方式。
其他物流方式条件必填物流选择其他时非空。
佣金比例必填0–100，默认 0。

采购经验、客户配合度、决策角色、项目预算档位选填填写时须为有效选项。
预算金额/区间选填保存客户预算描述；文字区间不充作确定的项目金额。

项目编号、评分/等级、设计状态、创建/修改人及时间系统生成或计算编号唯一；评分与设计状态按各自保存来源计算，不能由表单直接指定。

1.2.2 项目空间

入口：项目详情 / 项目档案 → 编辑项目 → 项目空间；分配商机 → 区域内 / 跨区域
操作人：PM

  • 创建时空间选填；产品商机分配时必填。每个空间保存稳定标识、名称与顺序，名称去除首尾空格后须非空且项目内唯一。空间不填写采购品类。
  • 产品分配带出当前空间，可编辑并回写项目；设计服务隐藏空间区域，不校验或回写空间。切回产品分配时保留未提交的空间输入。
  • 所有新旧产品商机及加单均按项目当前完整空间及名称校验。SM 只在需要的空间填写产品，其余空间允许空产品列表；空间顺序不参与一致性校验。
  • 增删或改名保存前，列出前后空间、受影响商机及品类、可编辑报价、任务及客户确认。用户核对后，原子保存空间及相关业务结果。
  • 受影响可编辑报价转已保存，两端标为待更新、未确认，恢复精确关联报价任务。原产品按空间标识保留，删除空间不直接删除产品，由 SM 归置后重提。仅调序保留有效报价和确认。
  • 历史提交、历史确认及已备货或后续订单使用原快照。空间已被他人更新时拒绝过期提交；保存失败回滚本次空间、报价、确认及任务变动。

1.2.3 项目列表与统计

入口：项目管理 → 列表及顶部卡片
操作人：有项目查看权限的人员

  • 列表按创建时间倒序，支持项目号、名称、客户等查询和列设置；每行展示项目状态、设计状态、人员、区域、金额及创建时间，提供详情、商机进度、报价总览、费用订单、查看待办等适用操作。
  • 过程卡片：项目数、非设计、设计类、待处理待办、待拉商机、停留超 10 天。设计类取实际设计商机或设计任务关系；非设计为当前范围内其余项目。
  • 过程卡片筛选当前项目列表，再点一次取消；切换卡片替换上一指标筛选。待处理待办卡片跳转对应项目范围的待处理任务，后续新任务自动进入范围。
  • 金额区单独展示项目金额、成单金额和实收；按最终筛选结果计算，费用计入规则见「费用金额统计」。金额卡片筛选有对应金额的项目。文字预算区间不作为确定金额。

1.2.4 项目状态与设计状态

入口：项目管理 / 项目详情 / 项目档案
操作人：系统计算；有维护权限的负责人办理输单

  • 项目成交状态按已承接正常商机计算：均未交付为待成交；部分进入交付中或正常完成为部分成交；全部进入交付中或正常完成为全部成交。前置邀请不作为已承接商机。
  • 待成交项目可填写原因后手动输单，操作不可逆；项目输单与各商机输单分别记录。
  • 有关联未完成设计交付或 PM 审核时为设计中；相关交付及对应审核均完成为已设计；没有设计任务时设计状态为空。
  • 费用订单的创建、传输、收款及完成只影响费用记录和金额，不推动项目或商机状态。

1.2.5 商机进度

入口：项目管理 → 操作列 → 商机进度；项目详情 → 商机进度
操作人：有该项目及商机查看权限的人员

  • 右侧抽屉按待接受、洽谈中、报价中、待下单、交付中、已完成、已拒绝、已输单分列，默认显示全部阶段；主流程表头使用带颜色的箭头体现流转。
  • 支持品类筛选和顶部统计卡片筛选，再点已选卡片取消。向下浏览时固定到品类筛选行，各阶段列独立上下滚动，按住鼠标拖动可横向浏览。
  • 商机卡片显示名称、品类 / 设计服务、负责人、客户、关联项目、商机金额、成单金额、实收、当前状态停留及报价任务；仅加单显示加单标签。前置卡片仅提供原关联待办操作。
  • 顶部汇总项目状态、商机数（含加单 / 设计数量）、待处理待办、超 10 天、商机金额及成单 / 实收。查看待办按精确关联定位，关闭抽屉保留原列表筛选及位置。

2. 待办中心

需求项需求说明
分类、列表与搜索按采购、设计、审批及其他待办分类，结合关系和业务范围查询。
办理权限与完成条件授权人员完成关联业务后，同步完成同一待办。

2.2 需求明细

2.2.1 分类、列表与搜索

入口：待办中心；项目 / 商机列表及详情 → 查看待办
操作人：有对应业务和待办查看权限的人员

  • 采购待办包含分配商机、采购商机接单、产品报价；设计待办包含设计商机接单、设计报价、设计中、设计定稿；审批待办包含跨区域商机审批、转介绍商机审批；其他待办包含费用订单。接单与报价根据关联商机的实际类型分类，分类只影响查找，操作权限按具体归属和状态校验。
  • 分类数量按当前授权范围、关联项目或商机、搜索及待办状态统计，正数以红色提示。切换采购或设计分类只显示对应类型的任务；原任务编号、负责人、业务关联及历史保持连续。
  • 支持全部 / 我负责 / 我发起、类型、状态、人员、停留时间和关键词。可搜索项目号、BU 商机号、客户及业务关键词；默认本轮到达时间倒序，用户主动选择的排序在筛选、常规刷新后保持。
  • 卡片展示适用品类、加单、已报价、已确认及当前待办状态标签。副标题以业务名称及编号识别记录：报价任务展示关联商机名称和已有单据号；设计交付与审核展示对应 XF 设计单号；项目、确认商机及费用待办展示项目名称和项目编号。展示负责人、发起人、到达时间、期望时间及停留时长，报价任务显示对应报价的客户确认结果。
  • 查看待办按项目或精确商机关系动态查询，包含后续新任务。单条范围在搜索栏显示项目号或 BU 号，批量范围用提示条表达；新业务导航替换旧范围，手动新搜索替换旧关联范围。
  • 待处理卡片进入时默认待处理；行级查看待办可切换历史状态。切换类型保留当前项目或商机范围，不混入其他品类、加单或项目任务。

2.2.2 办理权限与完成条件

入口：待办卡片 → 办理；对应项目 / 商机 / 报价业务入口
操作人：当前负责人；发起人按编辑权限操作

  • 卡片直接显示当前可用操作，办理和编辑使用右侧抽屉。打开及提交均重新校验身份、业务权限、当前状态及版本；查看权限不代表代办权限。
  • 分配商机任务由 PM 编辑项目或分配商机；下游邀请 / 审批保存成功后完成源分配商机任务。编辑项目和打开页面均不完成待办；后续可从项目详情继续分配。
  • 确认商机、设计审核、报价及费用办理的完成条件分别见对应模块；其他授权入口完成同一业务时，同步完成精确关联待办，不要求返回重复办理。
  • 分配商机、承接 / 驳回及确认报价成功后刷新原页面；从报价任务创建 / 编辑并提交报价后回到待办中心。关闭抽屉保留列表筛选和位置，有未保存输入时提示离开确认。
  • 业务保存和关联任务同次成功或同次回滚。权限失效、校验或保存失败保留输入及原状态；同次重试返回原结果，不创建重复业务。

2.2.3 驳回、编辑与重提

入口：待办中心 → 我发起 / 关联待办 → 编辑待办
操作人：支持驳回类型的原发起人；当前负责人办理驳回

  • 驳回须填写原因，保存后通知原发起人。设计确认按单张图纸驳回并通知 GDS，由原设计师在 GDS 修改该图后回传原审核任务。
  • 支持整项驳回的待办由原发起人在待处理或已驳回时编辑重提，已处理只读。设计定稿在 CRM 提供逐图审核和同步入口，图纸修改重提由 GDS 办理。正常报价编辑按其各自规则开放。
  • 载入原字段及附件，执行该类型相同的必填、人员资格和重复业务校验；排除原申请自身，不免除现有商机或其他未完成申请的冲突。按钮为「重新提交待办」。
  • 重提沿用原编号及来源。已驳回恢复待处理，当前驳回标记和原因转入历史；待处理有实际修改时记录新提交。保留历次申请、前后值、驳回、提交人与时间。
  • 待处理实际修改提交成功通知当前负责人“信息已更新”；已驳回明确重提成功通知“已重新提交”，即使内容未改也恢复待处理。取消、失败、无实际修改的待处理保存不发新通知。
  • 提交时核对最新版本；他人已办理或修改须重新核对。同次重试只保存同一结果、发送同一事件。

2.2.4 待办停留与期限提示

入口：待办中心 → 待办列表
操作人：各待办发起人、负责人

  • 待办按本轮实际到达时间计算停留，完成后显示处理用时；常规编辑不补造历史到达时间。
  • 已有明确业务期限的任务，当前待处理且超过期限时标记逾期；历史缺值显示未设置。
  • 设计单交付任务携带已确认设计单信息，设计中任务和图纸确认按实际提交、逐图审核结果推进。停留提示本身不完成任务或推进商机。

2.2.5 催办

入口：待办卡片 → 催办；项目 / 商机 → 查看待办 → 催办
操作人：当前待办发起人，负责人须为他人

  • 只对待处理任务提供催办；自办项目任务没有催办。报价任务由当前项目 PM 发起，负责人为商机 SM 或设计师，PM 可按规则催办。
  • 同一精确待办滚动 24 小时最多成功一次。刷新、换入口、交接或重提不清除冷却；显示上次成功时间、历史及下次可用时间。
  • 提交时校验当前发起人、负责人、权限、状态和冷却，并发和重复点击只创建一次有效催办。成功发送企微后计成功时间；失败不占额度，结果未知先核对原请求。
  • 通知包含实际催办人、当前负责人、项目、任务、期望日期和逾期情况；催办不改变任务状态或期限。

2.2.6 附件

操作人：有该业务查看 / 维护权限的人员

  • 支持多文件选择、拖拽、粘贴图片、上传进度、失败重试、预览、移除和下载；保存文件名称、业务关联、上传人及时间。
  • 按配置校验文件类型、大小和数量，上传未完成时阻止业务提交并提示；成功保存后才作为正式业务资料及评分来源。
  • 附件继承对应业务权限；客户只可查看明确对客发布的图片和资料，内部需求、审批证据不进入客户报价描述。历史使用当次保存的附件。

2.2.7 项目总览与项目档案

入口：项目档案按钮；项目总览；关联待办 → 查看档案
操作人：有项目查看权限的人员；维护由有权限 PM 操作

  • 展示客户基本资料、项目类型 / 规模 / 交期 / 物流 / 预算、项目人员、空间、现场及图纸附件、描述备注、评分等级、商机 / 报价 / 订单关联及设计状态。每项注明实际来源，缺值显示未记录。

  • 有权限 PM 可编辑项目及附件；保存后各入口读取同一资料并保留前后值、修改人、时间、来源。只读用户不能修改，评分和状态由实际来源计算。

2.2.8 项目评分与等级

入口：项目总览 / 项目档案 / 商机详情 / 关联待办 → 评分及等级
操作人：系统计算；有查看权限人员查阅，有维护权限人员修改来源

  • 逐项展示取值、来源、得分 / 满分、总分、等级、计算时间和历史。产品品类按已承接商机去重；同品类加单不重复计类。设计需求取已承接设计商机及有效设计师，附件按项目实际保存的文件组计一次。
  • A：总分 ≥140，且类型和规模已填、已承接产品品类 ≥2、交期 ≤9 个月、存在参与计分的客户图纸附件或任一类设计图纸；全部条件须满足。B：100–139，或 ≥140 但 A 条件不足；C：60–99；D：<60。
  • 九个月内包括已封顶 / 前期规划、毛坯 / 即将装修、精装 / 装修中、旧改 / 翻新。达到 140 仍为 B 时，逐项列出未满足的 A 条件。
  • 首次项目保存、计分资料保存、商机承接或设计师关系、客户属性、邀约日期等有效更新后重算，保存依据及前后结果。未保存预览不作正式结果，失败保留原评分。
  • 例：客户属性5＋国家5＋别墅30＋1000–2000㎡20＋两个品类20＋6–9月20＋设计商机及设计师20＋两组图纸30＋到店0＋SCRM0＋DDP5＝155，A 条件齐全为 A；仅一个品类合计145，因品类不足为 B。
  • 各内部入口读取最新已保存等级，历史保留当时结果。评分不等同现实真实性、审批结论或成交，不创建 / 完成待办，也不改变报价和客户确认。
计分项 / 满分规则
客户属性 / 5已填写有效客户属性得 5 分；未填写得 0 分。各类客户属性采用相同分值。
项目所属国/地区 / 5已选择国家/地区得 5 分；未选择得 0 分。
项目类型 / 30别墅、房地产项目（住宅综合体）得 30 分；公寓/平层、样板房、其他自建房、商住项目、办公空间、商业空间、零售空间及其他类型得 20 分；未选择得 0 分。
项目规模 / 300–300㎡、300–500㎡、500–1000㎡均得 10 分；1000–2000㎡得 20 分；2000–3000㎡得 25 分；3000㎡以上得 30 分；未选择得 0 分。
采购品类数量 / 30项目内已承接产品商机的品类去重后，1 个得 10 分，2–3 个得 20 分，4–5 个得 25 分，6 个及以上得 30 分，无有效品类得 0 分；同品类加单只计一次。

设计需求 / 20项目存在至少一个已承接设计商机得 10 分，该设计商机关联有效设计师再得 10 分；本项最高 20 分。
设计资料 / 30已成功上传并保存关联本项目的客户图纸附件得 10 分，平面设计图、3D意向图、全屋3D图、其他图任一组有有效文件得 20 分，四类合计仅计一次；与客户图纸附件累加，最高 30 分。
预计到店时间 / 10关联邀约记录中已有预计到店日期，得 10 分；无日期得 0 分。项目表单只读显示，不以手工填写项目备注代替邀约日期。
SCRM 回复效率 / 5本期固定计 0 分，保留该项 5 分权重，总分分母仍为 200 分。

2.2.9 SCRM 字段核对

入口：项目档案 → SCRM 字段核对 → 获取 / 刷新 / 采纳
操作人：同时有项目和会话权限的人员；采纳保存须具备字段维护权限

  • 选择关联客户 / 项目、会话来源和时间范围；仅提取能归属当前项目的内容。核对客户属性、国家、类型、规模、采购品类、交期、到店及物流；未提及不补写。
  • 逐项展示档案值、提取值、一致 / 存在差异 / 待核实，以及渠道、会话对象、消息时间、原文和获取时间；可打开原记录。表达不明、来源冲突或项目归属不明均待核实。
  • 用户选择采纳 / 不采纳并填处理说明。采纳先进入待保存修改，再按相应字段权限及业务校验提交；客户和邀约字段在其维护入口保存，正式采购品类由商机业务建立。
  • 涉及空间先核对报价 / 任务 / 确认影响；会话附件需人工确认归档并成功保存。保存保留原值、新值、证据、人员及时间，并重算相关评分；获取或选择采纳本身不覆盖资料。
  • 编辑期间来源变化须核对最新值；失败保留上次成功结果和时间，空来源或部分不可用说明原因并可重试。原记录链接继续校验来源权限。

2.2.10 真实性评估与智能总结

入口：项目档案 → 真实性评估 / 智能总结
操作人：有项目及来源查看权限人员；PM 按权限保存核实记录

  • 真实性评估展示核对范围、来源、时间，以及一致 / 差异 / 待核实的事项和数量；字段一致不等于项目现实真实，结果不显示真实概率。
  • PM 可补充证据和核实说明，标记待核实 / 已核实并保留人员时间。标记不自动改档案；采纳资料通过 SCRM 核对或正式维护入口保存。新增矛盾形成新差异，保留此前核实依据。
  • 智能总结通过生成 / 刷新汇总当前项目资料、关联客户及有权会话，包含客户背景、需求、项目条件、空间品类、交期、图纸、关注点、已确认及待核实事项；展示资料范围、生成时间和来源。
  • 原话、已保存值与归纳结论可区分；缺少证据明确列出，不虚构承诺。资料变化提示刷新；失败保留上次成功内容及时间。
  • 评估和总结不自动计分、修改资料、办理任务或对客发布。实际采纳保存涉及计分来源时才重算。

  • 分配类型必选，默认区域内分配，另有跨区域申请、设计服务。同一项目可同时开展产品和设计业务。

3.2.2 跨区域申请

入口：分配商机任务 / 项目详情 → 分配商机 → 跨区域申请
操作人：PM 发起；当前总经办审批人员办理

  • 方案经理必选，可搜索多选，仅显示负责项目区域外且符合品类资格人员；申请原因必填，申请附件选填，项目空间带出可编辑且提交必填。
  • 提交为各申请生成独立总经办审批待办；成功保存空间及下游任务后完成源分配商机任务。
  • 审批人查看项目、品类、接收 SM、原因及附件，点击通过直接生成正常商机和 PM 发起的报价任务，并反馈 PM、通知 SM，不再追加承接邀请。
  • 驳回须原因，PM 编辑原申请重提。提交和审批均校验人员资格、权限、当前项目空间及重复业务；失败保持原申请及状态。

3.2.3 设计服务分配

入口：分配商机任务 / 项目详情 → 分配商机 → 设计服务
操作人：PM 发起；被选设计师主管承接

  • 必填设计师主管（可搜索多选）、设计期望完成时间、是否需要协调员。协调员选项为“是，由设计师安排”“是，我安排人员”“否，我自己确认”；选择由 PM 安排时，必须从有效人员中选择协调员。设计服务分配不校验或回写产品空间。
  • 界面备注：协调员将协助与客户确认设计图纸，完成设计定稿。每位主管的商机接单展示期望完成时间与协调方式；承接后保存到精确商机，设计单确认报价时写入设计中任务，并同步 GDS。
  • 每位主管收到独立商机接单，查看项目、附件、备注和发起 PM。提交成功完成精确源项目任务；后续仍可从项目详情分配其他业务。
  • 主管确认后生成设计商机及 PM 发起的报价任务。负责人填写设计费用、附件和备注，提交并确认设计单报价时，生成对应设计中任务并携带设计单信息同步 GDS。
  • 拒绝保留原因并通知 PM，由 PM 编辑原邀请重提；实际接受成功后才建立正常商机及关联报价任务。

3.2.4 承接与重复校验

入口：商机接单 → 确认 / 驳回；项目详情 / 商机管理 → 前置记录操作
操作人：指定 SM / 设计师主管；跨区域由审批人员办理

  • 待接受、已拒绝均为前置邀请，使用正常业务命名规则，展示在项目与商机列表；只开放原待办操作，不允许创建报价、加单或直接输单。
  • SM 或设计主管确认邀请均生成商机及报价任务。办理成功留在原入口，失败不生成下游；重复承接返回原商机和任务。
  • 区域内（含转介绍）和跨区域共同按项目品类校验原始商机与未完成申请，项目每个产品品类只有一位当前 SM；设计按项目和接收主管校验已有商机及未完成邀请。
  • 打开、提交、审批及重提均检查资格、当前负责人和冲突，重提排除自身申请。追加需求通过「商机加单」独立办理。

洽谈中负责人已接受商机；创建该商机唯一报价单后转报价中。

待下单负责人确认报价后进入。产品按实收≥20% 且有产品信息校验备货条件，再由 PM/SM 在 ERP 点击备货；设计单尚未实际收款时保持本阶段。
交付中产品以 ERP 实际备货或生产结果进入；设计以该设计单实际实收大于零且尚未收全进入。设计审核完成或付款申请不能代替实收。
已完成产品关联订单正常交付结束；设计单实际累计实收达到该单金额。设计首次回款即收全时直接进入已完成。
已输单有操作权限的负责人手动记录原因并输单，操作不可逆。已完成商机不允许输单；前置记录按原待办确认或拒绝处理。

4.2.3 方案经理交接

入口：项目详情 → 商机列表 → 修改方案经理
操作人：有项目维护及交接权限的人员

  • 选择符合该品类及适用区域资格的新 SM；同项目同品类始终一位当前 SM，原单和加单统一移交。
  • 保存后更新商机、报价编辑和未完成任务归属，以及两个报价总览显示；原编号、空间、状态、到达时间、已填内容、发布版本、客户确认和订单保留。
  • PM 交接同步对应项目任务及未完成职责，报价任务发起权归新 PM；客户、PM 和商机人员分别交接，不自动更换其他职责或设计师。
  • 历史发起人、处理人、提交人和通知人员保持当时记录。客户无需因交接重确认；保存失败维持原归属。

4.2.4 商机输单

入口：商机管理 / 项目详情 / 商机详情 → 输单
操作人：有该商机输单权限的负责人

  • 仅正常且未完成的商机可输单，原因必填，保存后为已输单且不可逆；前置邀请通过原待办拒绝，已完成商机不可输单。
  • 商机和项目的输单分别处理。保留报价、订单、客户确认及办理历史，失败保持原状态。

5. 商机报价与 ERP

6 项需求

5.1 需求列表

需求项需求说明
产品报价单每商机一张报价，使用现有线上报价模板填写产品。
设计单设计商机按服务费用报价，创建确认后发布两端总览。
保存、提交与客户确认区分内部工作稿、正式发布及客户确认。
负责人确认报价确认已提交的有效版本，完成原报价任务并提交 ERP。
ERP 收款与履行ERP 实际回执驱动交付，产品和设计使用各自条件。
商机加单已承接产品及设计商机可在各阶段追加独立需求。

5.2 需求明细

5.2.1 产品报价单

入口：产品商机详情 / 报价任务 → 创建 / 编辑报价单
操作人：当前商机 SM

  • 记录项目、商机、当前负责人、品类、原单 / 加单和精确报价任务关系；重复创建返回已有报价。
  • 带入项目当前全部空间，SM 在所需空间录入本次产品；其余空间保留空产品列表。报价内容只属于本商机品类；产品选择、模板字段及计算沿用现有报价能力。
  • 保存仅更新工作稿，两端继续使用最近有效提交。产品提交须匹配完整当前空间及名称，不校验顺序；空间版本变化提示按最新范围核对。

5.2.2 设计单

入口：设计商机详情 / 报价任务 → 创建 / 编辑设计单
操作人：当前设计商机负责人

  • 字段：设计费用必填，附件、备注选填；附件可上传相似作品供客户查看。只有设计商机具备该入口，设计单属于该商机唯一报价。
  • 确认创建校验有效费用、附件和商机关联，发布两个总览并保存成功提交历史；后续保存只更新工作稿，重新提交发布新版本。
  • 设计服务不校验产品空间；设计任务和 PM 审核完成与否不限制设计报价。仍由报价任务「确认报价」提交 ERP 并完成任务。
  • 设计单及费用订单沿用既有 XF 开头单号，系统生成并保持唯一；单号是任务、项目和 ERP 记录的关联依据。

5.2.3 保存、提交与客户确认

入口：报价编辑 → 保存 / 提交；客户报价链接 → 确认报价
操作人：SM / 设计负责人；客户

  • 待报价：已创建尚未保存；已保存：工作稿已保存；已报价：本次提交成功；已确认：客户确认该发布版本。负责人确认报价和 ERP 执行另记结果。
  • 产品提交校验商机权限、唯一报价、品类、当前完整空间和模板适用规则；设计按服务费用及资料校验。保存不发布、提交失败不对客生效。
  • 提交成功原子更新项目及客户总览，保存不可覆盖的报价快照、提交人和时间。重新提交发布新版本，使该批次当前客户确认恢复未确认；历史继续可查。
  • 仅保存、提交或客户确认均不完成报价任务；从待办创建 / 编辑并提交后留在待办中心，供负责人继续确认。重复提交同一请求不新增历史或重复通知。

5.2.4 负责人确认报价

入口：报价任务 / 商机报价行 → 确认报价
操作人：当前商机 SM 或设计负责人

  • 允许已报价或客户已确认的当前有效版本；客户确认不是前置条件。已保存编辑稿、待更新或冻结后不允许的版本不能确认。
  • 成功保存实际确认人、时间、报价及价格版本和 ERP 请求，完成该商机及报价单的精确报价任务，并独立通知当前 PM；办理后刷新原页面，待办中心办理继续留在待办中心。
  • 报价任务由当前项目 PM 发起、商机负责人负责；客户确认只更新报价确认记录，不代替负责人操作。
  • 请求初始 ERP 执行状态为未执行；请求、接收、实收与执行分别记录。同版重复确认返回原结果，失败不完成任务、不发送成功通知。

5.2.5 ERP 收款与履行

入口：ERP → 关联产品报价订单 / 设计单；CRM → 回执结果
操作人：财务在 ERP 收款；产品备货由 PM / SM 在 ERP 操作

  • CRM 发送精确项目、商机、报价 / 订单、版本和金额。ERP 接收、实收、备货 / 生产和完成回执分别留存，重复回执不重复计款，旧版本不能覆盖新业务结果。请求或付款申请不代表真实收款。
  • 产品先完成正式报价并确认再收款。该产品订单实收 ≥订单金额20%，且有产品信息后，由 PM / SM 在 ERP 点击备货；实际备货或生产进入交付中，正常交付结束进入已完成。
  • 设计单确认报价后待下单；该设计单实际实收 >0 且未收全进入交付中，实收达到单金额为已完成，首次收全可直接完成。费用实收不抵设计单收款门槛。
  • 设计收全款不完成设计交付 / PM 审核，也不屏蔽其正常催办。费用状态与主业务阶段分别处理。
  • 产品备货前重新提交更新同一关联订单的报价版本，保留单号、真实实收和执行记录；普通保存不更新已发布或 ERP 内容。已备货及后续原报价 / 订单冻结，新增需求通过独立加单。
  • 接收或发送失败保留原内容及可追溯重试；确认成功后的发送失败不伪造 ERP 成功或撤销已保存办理结果。

5.2.6 商机加单

入口：商机列表 / 详情 / 项目商机行 → 商机加单
操作人：有来源商机加单权限的人员

  • 不设备货或确认报价的开放门槛；校验来源、当前负责人及操作权限，自动记录承接完成并生成独立加单商机和 PM 发起的报价任务。
  • 沿用当前负责人并保存来源商机 / 原订单关系。设计加单同步生成对应设计任务，交付与报价仍并行。
  • 产品加单使用项目完整当前空间，只录本次新增产品及数量，空空间允许无产品；设计加单按新增服务及费用报价。
  • 原单与每次加单分别发布、确认、计款和保留历史，本次客户确认不要求重确认原单或其他加单。

6.1 需求列表

需求项需求说明

6.2 需求明细

6.2.1 直接创建费用订单

入口：项目 / 商机详情及列表 → 费用订单 → 创建费用订单
操作人：有权限项目负责人或商机负责人

  • 字段：费用类型、金额必填；附件、备注选填。项目入口可关联具体商机或作为项目费用，商机入口固定当前商机。
  • 费用类型按系统配置，金额为大于零的有效数，附件须上传成功；校验当前项目 / 商机及维护权限。
  • 成功创建费用订单并记录 ERP 传输请求。项目费用留在项目订单列表；商机费用同时出现在商机及所属项目中，以同一订单身份保存。订单类型和费用类型分别展示。
  • 费用订单独立于商机唯一报价，保留创建人、时间及附件备注；同次重试不重复订单或 ERP 请求。

6.2.2 发起与办理费用订单待办

入口：费用订单 → 发起费用订单待办；待办中心 → 费用订单待办 → 确认
操作人：项目 / 商机负责人发起，当前经办人办理

  • 发起字段：费用类型、待办人必填，附件、备注选填；发起时不填金额。保存独立费用订单待办及项目 / 来源商机关联，通知经办人。
  • 确认界面展示费用类型、发起人、经办人、原附件与备注；经办人必填费用金额，可补充 / 调整附件与备注。原申请资料和本次经办资料分别留存。
  • 确认成功按该费用类型创建订单、提交 ERP，并完成精确原待办；费用订单及 ERP 请求携带经办资料。旧界面提交须校验最新任务及版本，失败不创建订单或结束任务。
  • 经办人可填写原因驳回，发起人编辑同一原待办重提，恢复待处理并通知当前经办人；允许按人员校验调整待办人。编辑、驳回及催办按「待办中心」通用规则。

6.2.3 费用金额统计

入口：项目 / 商机列表、详情及商机进度 → 金额
操作人：系统按当前查询范围汇总

  • 创建成功的费用金额计入对应项目金额及成单金额；关联商机的费用还计入该商机金额及成单金额。项目直属费用只计项目，不分摊到其他商机。
  • 实收取该费用订单实际 ERP 收款，未有真实回款不增加实收。ERP 请求、失败或执行状态不代替收款金额。
  • 项目汇总包含项目直属和商机费用，同一费用订单按唯一订单号只计一次；同一订单出现在项目和商机列表不重复相加。筛选只累计当前范围内的关联费用。
  • 例：产品商机金额1000、成单600，新增关联费用300后，商机金额1300、成单900；项目另有直属费用200，则项目费用增量为500，商机仍只增加300。
  • 费用的创建、传输、收款、备货或完成均不推进项目 / 商机阶段，也不改变产品或设计报价状态、客户确认及报价任务。

  • 展示项目 / 客户 / PM 资料、完整空间导航、品类和加单、负责人、提交 / 客户确认状态及时间、金额卡片和品类占比。每批次读取当前有效成功提交。
  • 支持空间、品类、原单 / 加单及搜索，原单和各加单独立标识；设计服务按对应商机服务内容展示。当前清单及两端历史使用「客户清单字段」同一16项字段。

7.2.2 项目币种、汇率与客户链接

入口：项目报价总览 → 币种 / 汇率、客户预览、复制链接
操作人：PM 维护计价；有链接权限的内部人员预览 / 复制

  • 必填目标币种和汇率，新项目 CNY、1。可获取汇率或手填，记录来源、数据日期、配置版本及保存人时间；CNY固定1，其他汇率须>0。
  • 1目标币种＝r CNY，目标金额＝CNY÷r；如720元、汇率7.2，显示$100.00。各行按币种精度四舍五入后累加汇总，单价可保留更高精度；页面、确认和导出共用结果。
  • 预览默认英文，可切语言；预览、复制链接及商机历史展示沿用项目设置，操作不改变报价或待办。复制失败提供可选中地址，获取汇率失败保留原设置并可手填。
  • 计价版本参与客户确认校验；变化后受影响未备货批次需核对最新价格。历史提交、确认及冻结订单保留原计价快照。链接刷新读取最新有效发布数据，不依赖重新部署。

7.2.3 提交更新与报价历史

入口：项目总览 → 右上角报价历史；商机报价行 → 报价历史；客户确认区 → 历史
操作人：内部按报价权限；客户只查看授权对客历史

  • 每次完整发布更新同一报价的当前明细、负责人、金额、提交时间及客户确认，原单和各加单分别更新。新版客户确认恢复未确认，旧版本与确认记录不可覆盖。
  • 历史抽屉按品类、报价单 / 原单或加单、提交版本选择，展示提交人、时间、金额、报价 / 价格版本、确认记录、清单及当次图片。商机行入口仅限该张报价单。
  • 客户从品类进入默认该品类，全部品类入口先选具体品类。商机历史默认中文，展示金额跟随项目计价，同时标明原提交币种和汇率，不改原快照。
  • 点击历史空间名查看当次图片；缺少历史 / 图片明确未记录，不以当前值补造。历史不可修改或重新确认，不参与当前合计；关闭保留原筛选和位置。
  • 重复同次提交、普通保存和失败不新增历史。CRM 接收失败不发布半份报价，旧版本晚到不能覆盖新版；已因空间失效的内容只供历史查阅。

  • 金额、已确认金额、品类数及计价随查看范围更新；清单关键词仅筛选显示行，不缩小批次汇总或确认范围。个人筛选、展开和滚动互不影响。

8.2.2 客户清单字段与图片

入口：客户清单 / 项目清单 / 报价历史 → 明细
操作人：当前页面有权限的查看人

  • 16项字段为序号、空间、品类、产品编码、产品名称、产品图片、尺寸规格、产品描述、单位、数量、单价、金额、体积、重量、状态、备注；字段展示规则见下表。
  • 清单支持横向浏览、搜索和滚动表头固定。产品主图与大图一致，支持多图切换 / 放大；空间名可查看对应空间多图，图片保持原比例，失败可重试。
  • 未确定产品隐藏编码和商品图。描述展示对客文字及允许的报价图片，包括石材、加工、墙板和陶瓷等模板图片；内部需求和审批证据按内部权限查阅。
清单字段读取与展示规则
序号 / 空间 / 品类展示报价行序号、空间名称和产品所属品类；点击空间名称查看对应空间行图片。
产品编码 / 产品名称 / 产品图片展示编码、名称及多图入口，图片保持完整比例；未确定产品隐藏编码及商品图。
尺寸规格展示尺寸规格及对应单位。
产品描述展示产品描述及允许对客的模板信息和图片，包括石材应用图、加工图、墙板效果图和陶瓷区域图片等。
单位 / 数量展示报价单位及数量。
单价（币种）/ 金额（币种）列名带币种代码，值带币种符号。当前报价按项目已保存价格配置换算；历史报价保留提交时币种与汇率。商机详情的历史金额按项目总览已保存设置换算展示，同时保留提交时计价记录，不改写原始快照。
体积(m³) / 重量(kg)展示体积、重量；缺失时显示空或横线。
状态 / 备注展示该报价版本的报价和确认状态，以及该次提交的报价备注。

8.2.3 客户直接确认

入口：客户清单 → 选择品类及批次 → 确认报价
操作人：持有效授权链接的客户

  • 核对该批次全部应确认空间 / 设计服务内容、币种汇率、金额和报价版本后直接确认，无验证码。搜索或单空间筛选不缩小完整确认范围；加单只确认本次新增需求。
  • 提交校验链接、项目授权、当前报价及计价版本、空间范围和变更状态。内容变化须重新核对，旧页面不能确认新版本；待更新或历史版本不可确认，仅调序保留确认。
  • 保存项目、商机、品类、原单 / 加单、报价和价格版本、范围、金额及确认时间，两端同步更新并通知当前 PM 和负责人。
  • 客户确认不完成报价任务、不自动传 ERP。重复确认返回原记录且不改首次确认时间；失败不标已确认；新版确认与旧历史分开保存。

8.2.4 访问权限、手机与语言

入口：客户报价链接 → 语言、图片、历史、确认
操作人：授权客户

  • 链接只读取授权项目对客数据，可撤销并显示失效提示；修改project参数不能读取其他项目。内部客户档案、成本、利润、审批证据和内部总结不对客发布。
  • 手机保留空间、品类、语言、历史和确认入口，表格可横向浏览，产品和空间图片可多图查看。加载或资源失败说明原因并可重试，保留选择及已保存记录。
  • 默认英文，支持英文、简体中文、西班牙语、法语、阿拉伯语、俄语。界面、状态、按钮和表头本地化，产品读取对应语言，缺失按约定备用语言；阿拉伯语方向正确，图片保持原比例。
  • 切换语言不改价格、汇率或确认状态；同一有效链接持续读取各批次最新发布结果。

9. GDS 设计协作

2 项需求

9.1 需求列表

需求项需求说明
设计单同步与图纸回传设计单确认报价生成设计中任务；GDS 可分批回传图纸，并独立决定设计任务完成。
逐张图纸确认与重提逐图确认或驳回，全部确认后由 PM 或指定协调员手动同步项目并完成审核。

9.2 需求明细

9.2.1 设计单同步与图纸回传

入口：设计单 → 确认报价 → GDS 设计中任务 → 回传图纸
操作人：设计商机负责人确认报价；GDS 授权设计师办理

  • 负责人确认设计单报价后，系统生成唯一关联设计中任务并同步 GDS，同时完成原报价任务及记录 ERP 请求。重试复用同一设计任务，费用订单不生成设计任务。
  • 设计中任务展示设计单号、设计费用、关联项目与商机、设计师主管、设计单附件和备注，以及分配时填写的期望完成时间、协调方式与指定协调员。设计单号及费用必须来自精确关联设计单。
  • GDS 设计师决定回传的图纸，按平面设计图、3D意向图、全屋3D图、其他图分类；每张具有稳定标识、文件、版本及说明。每次回传至少一张有效图纸，同一任务可分批回传；当前审核未完成时追加新图，已有图纸沿原审核与重提规则处理。上一审核批次同步完成后，新回传另建对应批次审核，保留旧批次。
  • 图纸回传生成关联设计定稿，并不完成设计中任务。设计中任务仅在 GDS 发出有效完成回执时完成；完成图纸确认或项目同步均不代替 GDS 完成。GDS 完成也不自动完成未结束的图纸审核。
  • 由设计师安排协调员时，GDS 回传协调员身份及逐图确认结果；CRM 展示这些结果，PM 核对后手动同步项目信息。由 PM 指定协调员时，该人员与 PM 均可在 CRM 确认、驳回和同步对应图纸，操作记录实际处理人。
  • CRM 与 GDS 请求及回执检查系统、任务、项目、商机、设计单、处理人、事件标识和版本；重复回执返回原结果，陈旧版本、关联不符或保存失败不得改动任务、图纸或附件。

9.2.2 逐张图纸确认与重提

入口：CRM 待办中心 → 设计定稿 → 查看并处理；GDS → 原设计任务 → 被驳回图纸修改与回传
操作人：项目 PM / PM 指定协调员；原设计师处理驳回；GDS 协调员在 GDS 确认

  • CRM 列表在副标题显示关联 XF 设计单号；设计中任务和设计定稿沿用同一设计单关联。审核主操作为查看并处理，催办为次操作。审核界面展示设计单信息、期望完成时间、协调方式、协调员及本批全部图纸。每张独立展示类型、文件、版本、说明、状态、实际审核人及历史。打开界面不改变任务状态。
  • PM 或 PM 指定协调员可逐张确认当前待确认版本，或填写原因驳回该图。仅退回有问题的图纸给原设计师，同批其他已确认图纸保留结果；父审核待办保持待处理。选择由设计师安排协调员时，CRM 展示 GDS 已确认结果，PM 负责同步。
  • 原设计师在 GDS 修改被驳回图纸并回传 CRM。沿用图纸标识和原审核任务，追加版本及提交历史，清除该图当前驳回标记并通知 PM 及其指定协调员；已确认图纸不能覆盖。
  • 仅当本批全部图纸已确认，才可点击“同步到项目信息”。有待确认或已驳回图纸时不可同步；同步成功按类型归档到项目的四类图纸附件组、重算资料评分并完成本批设计定稿。其他附件、历史审核及产品空间保持关联。
  • 同步不完成设计中任务，设计中任务由 GDS 决定完成。同步操作校验权限与当前图纸版本；重复同步不重复归档；保存失败保持图纸、项目及任务原状。

10.2.1 事件与接收人

10.2.2 通知卡片与精确入口

入口：企业微信应用消息 → 查看待办 / 查看报价 / 查看结果
操作人：对应接收人员

  • 共用一个「敬城 CRM」自建应用，采用textcard。标题为业务事件；正文含时间、实际发起人、客户、项目、品类 / 设计服务、真实报价版本、批次、当次状态及原因摘要。
  • 发起人记录触发该事件的实际人员及当时姓名；客户未经身份认证时写“客户链接确认”，系统事件写“系统自动触发”，历史缺值写未记录。不展示私人手机号或待办内部修订次数。
  • 待办 / 审批通知进入待办中心精确搜索原待办，清理旧状态、人员和停留筛选，关系为全部；详情由用户主动打开。客户确认通知定位原报价任务，不进入旧订单待办。
  • 报价通知定位项目及品类，订单结果定位对应订单；登录后保留原目标，重新校验当前权限、归属和状态，已完成不重复办理。
  • 历史卡片保留发送时内容、发起人及原因，当前任务显示最新状态，旧驳回通知不恢复驳回。正文过长截为摘要，详情保留完整记录，动态内容转义并按接口长度校验。

10.2.3 去重、发送结果与催办

入口：服务端 → 企业微信发送记录；待办中心 → 催办记录
操作人：系统发送，有权限人员处理失败

  • 按业务事件、精确记录、报价 / 提交版本或状态变化及接收人去重。同次重试不新增通知；同一待办再次成功修改 / 重提必须生成新事件，不能只按待办号去重。
  • 状态为待发送、接口已接受、发送失败、结果未知。接口成功不等于已读 / 已办理；无效成员逐人记失败，超时先核对原请求。通知失败不撤销已成功业务。
  • 保存实际事件及版本、发起人和当时姓名、接收成员、应用、发送内容、触发时间、每次尝试、接口结果与重试次数；凭证仅服务端管理。历史已发内容不随交接或改名变化。
  • 重试沿用原事件；办理通知发送前核对最新归属，已发送历史接收人保留。防止重复建发送任务，但不承诺企微客户端绝对仅出现一次。
  • 催办按原待办滚动24小时限制，内容含实际催办人、项目、任务、期望日期和逾期情况；接口成功后计冷却，失败不占额度，结果未知先核对原记录。
  • 接入使用测试应用和成员验证手机 / PC、登录续跳、定向接收、完整原因及发送失败；实际业务完成仍取 CRM 成功保存结果。
